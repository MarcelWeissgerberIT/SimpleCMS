**Workspace → Integrations.** A profile names the MCP server it is for — by the tools of its last connection test, its name or its address — and what it unlocks while that server is switched on: the **Key** and **Only by hand** switches, **upsert_rows**, the **tool list** per server, the **agent state** and **notes** in your inbox. One presets no tool: you add the profile, or import one as a .json file. The LED says whether it is active here and why not.

**Recipes as configuration.** A profile can bring recipes, listed under **Agents → New agent** with its name. *Mirror tracker items*, say, creates a database for the tool's items — your own **My status**, **My priority**, **Next step** and **Due** set to *Only by hand* — six views such as **Board by Clarity** and **My week**, a report page and a weekday agent that updates rows by their key and leaves you notes like *“New comment on #8215”*. Database, views, schedule, budget, tools and instructions are all data in the profile; whatever it leaves out takes the built-in values.

**The editor** shows the profile's JSON with colours and line numbers and checks it as you type: a syntax error with line and column, a schema problem with its path, and **Valid · active here · unlocks … · 1 recipe** once it is right. **New integration** starts from the template or from one of your servers.

What is already set keeps working without a profile: keys stay unique, *Only by hand* stays closed to agents, an agent's tool list stays. In team workspaces owners and admins edit profiles; server agents match them by the server's MCP name or address.
