**Agents → New agent → Mirror a list into a database.** Pick the MCP server of your tool, a name and a page: One creates a database for the items — Key, Link, Source status, Owner, Comments, **New comment**, **Waiting on me**, **Clarity**, Why, Gone from source … — plus your own **My status**, **My priority**, **Next step** and **Due**, six views (**Board by Clarity**, **New comments**, **Ready to work**, **My week**, **As in the source**, **All**) and a report page. **Undo** takes it all back.

The agent opens ready to save: every weekday at 07:30, proposals first, only the server's reading tools. Replace the four parts in **[SQUARE BRACKETS]** — how to list the items, how to read one, who you are there, what *Clear* means — and save. Once the first runs look right, switch it to **Apply directly**.

What makes it safe, for any agent:
- **Key** — a property that identifies a row. Agents add new items or change only what differs, up to 50 rows in one step; a key another row holds is refused.
- **Only by hand** — properties agents never write: your status, priority and notes stay yours.
- **MCP tools** — tick which tools of a server an agent may use; **Read-only tools** keeps the reading ones.
- **Last run and state** — every run knows its last successful run and keeps a small state of its own, so it reads only what changed.
- **Notes for you** — *“New comment on #8215”*, *“3 items became ready”* land in your **Inbox**, linked to the row.

More in [Custom agents](help:custom-agents) and [Key and Only by hand](help:properties).
