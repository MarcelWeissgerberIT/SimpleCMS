**Every ship on the task page.** When the pipeline — or you, in the **Git** tab — commits, pushes or opens a merge request, the task page gets a dated note: *Commit a1b2c3d · Branch one/… · MR !42 · pushed to origin/…*, each part a link to your GitLab or GitHub. **PR / commit** holds the request, or the pushed commit when there is none. A commit whose push or request failed is noted too.

**Found again from GitLab.** The commits the worker makes for a task and its merge request description end with `One-Task: <task id>` — the task's **Git** tab shows the line, ready to copy. An open merge request is found again instead of a new-request link. A self-hosted GitLab or GitHub Enterprise under its own name: pick its **Host type** on the worker's setup page. A rejected push says what to do — the worker never force-pushes.

**A gate that always stops.** In **Pipeline**, set a gate to **Always stop here**: Approvals *None* runs past every other gate but waits there. New *Review & merge* pipelines set it for *Approve review & merge*. **Use for new tasks** in the coding panel now sets the default explicitly — picking for one task no longer changes others. The pipeline editor also warns when the worker has pushing or merge requests switched off for a repository.

Needs worker 1.10.0: **Download again** in Settings → Coding worker. More: [Coding pipeline](help:coding-pipeline).
