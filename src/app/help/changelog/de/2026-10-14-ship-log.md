**Jedes Ausliefern auf der Aufgabenseite.** Wenn die Pipeline – oder du im Tab **Git** – committet, pusht oder einen Merge Request öffnet, bekommt die Aufgabenseite eine datierte Notiz: *Commit a1b2c3d · Branch one/… · MR !42 · nach origin/… gepusht*, jeder Teil ein Link zu deinem GitLab oder GitHub. **PR / Commit** enthält den Request – oder, ohne einen, den gepushten Commit. Auch ein Commit, dessen Push oder Request scheitert, wird festgehalten.

**Von GitLab aus wiederzufinden.** Commit-Nachrichten und Merge-Request-Beschreibungen enden mit `One-Task: <Aufgaben-ID>`. Ein offener Merge Request wird wiedergefunden statt eines Links für einen neuen. Ein selbst betriebenes GitLab oder GitHub Enterprise unter eigenem Namen: Wähl auf der Setup-Seite des Workers seine **Host-Art**. Ein abgelehnter Push sagt, was zu tun ist – der Worker pusht nie mit Force.

**Eine Freigabe, die immer hält.** Stell in der **Pipeline** eine Freigabe-Stufe auf **Immer hier anhalten**: Freigaben *Keine* läuft an jeder anderen vorbei, wartet aber dort. Neue Pipelines aus *Review & Merge* setzen es für *Review & Merge freigeben*. **Für neue Aufgaben übernehmen** im Coding-Panel setzt den Standard jetzt ausdrücklich – die Wahl bei einer Aufgabe ändert keine andere mehr. Der Pipeline-Editor warnt außerdem, wenn der Worker Pushen oder Merge Requests für ein Repository ausgeschaltet hat.

Braucht Worker 1.10.0: **Erneut herunterladen** unter Einstellungen → Coding-Worker. Mehr: [Coding-Pipeline](help:coding-pipeline).
