**Neu herunterladen und neu starten.** **Einstellungen → Coding-Worker → Erneut herunterladen**, beende den laufenden Worker (<kbd>Ctrl+C</kbd>) und starte die neue Datei. **#/coding** nennt einen Worker, der älter als 1.8.1 ist, mit einer Taste zum Download.

**Eine ZIP bringt Code mit, sonst nichts.** Datenträger unter macOS und Windows ignorieren Groß- und Kleinschreibung – so konnte eine ZIP einen Ordner `.GIT` mitbringen, den git für den eigenen Ordner des Repositorys hielt, und dessen Einstellungen konnten beim Import ein Programm starten. Jetzt bleibt `.git` in jeder Schreibweise draußen, eine ZIP, die selbst ein Repository ist, wird abgelehnt, und der Import führt keine Hooks, Filter, gc oder fsmonitor aus. In einem importierten Repository bleiben deine eigenen Git-Treiber (Filter, Diff- und Merge-Treiber) aus.

**Eigene Einstellungen nur für deine eigenen Repos.** Claude Code lädt beim Start die eigenen Einstellungen eines Repositorys – `.claude/` mit seinen Hooks, `.mcp.json`, `CLAUDE.md` –, auch in einer Stufe, die nur liest. Bei einem Repository, das der Worker geklont oder importiert hat, startet es jetzt ohne sie. Die Setup-Seite des Workers (**Repositories ändern**) hat pro Repository den Schalter **Eigene Claude-Code-Einstellungen dieses Repos nutzen**, mit dem Grund, warum er aus ist; schalte ihn nur für Code ein, dem du vertraust. Deine eigenen Repositories bleiben, wie sie waren – außer sie liegen im Klon-Ordner des Workers (einem, den du gewählt hast, etwa `~/code`): Dort zeigen sie *im Klon-Ordner*, mit dem Schalter. MCP-Server für ein solches Repository fügst du mit `claude mcp add -s user …` hinzu. Was ein älterer Worker importiert oder nach `~/one-repos` geklont hat, wird einmal markiert – die Setup-Seite nennt es, bis du **Verstanden** drückst.

**Schon einmal eine ZIP von jemand anderem importiert?** Hat ein älterer Worker sie unter macOS oder Windows importiert, prüf dieses Repository. `git config --local --list` sollte nur die `core.`-Zeilen zeigen, die git selbst schreibt (`repositoryformatversion`, `filemode`, `bare`, `logallrefupdates`, `ignorecase`, `precomposeunicode`, `symlinks`), und, falls du es auf GitLab / GitHub veröffentlicht hast, seine Zeilen `remote.origin` und `branch.main` – sonst nichts, das du nicht selbst gesetzt hast, etwa `include.path`, `core.fsmonitor`, `core.hooksPath`, `core.sshCommand`, `credential.helper`, `filter.*` oder `gpg.program`. In `.git/hooks` sollten nur `*.sample`-Dateien liegen. Findest du etwas anderes, kann der Code der ZIP schon mit deinen Rechten auf deinem Rechner gelaufen sein – beim Import und bei späteren git-Schritten darin: Geh davon aus, dass der ganze Rechner betroffen ist, nicht nur das Repository. Lösch danach das Repository und importiere die ZIP mit 1.8.1 neu. Mehr: [Altsoftware modernisieren](help:legacy-modernisation).
