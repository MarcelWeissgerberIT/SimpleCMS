Jede Stufe, in der Claude Code arbeitet – Plan, Umsetzen, Dokument –, kann jetzt ihr **Modell** nennen. In der **Pipeline** (auf #/coding) öffnest du die Details einer Stufe und wählst **Opus**, **Sonnet**, **Haiku**, **Fable** oder **Eigenes …** für jeden anderen Modellnamen; **Standard** lässt die Vorgabe des Workers (das Modell des Repos in der `worker.json`, sonst die von Claude Code). Das Modell steht als kleiner Chip in der Zeile der Stufe.

Mit einem starken Modell planen und ein schnelleres umsetzen lassen – oder umgekehrt. Für eine einzelne Aufgabe legt **Modell** im Coding-Panel (neben den Freigaben) ein Modell für alle ihre Claude-Code-Stufen fest, auf diesem Gerät.

Während eine Stufe läuft, zeigt ein Chip unter **Jetzt** das Modell, das Claude Code wirklich nutzt, und das Log nennt das, das der Worker weitergegeben hat. Eine Stufe mit Modell braucht den Worker 1.5 – ein älterer bekommt sie nie: lade ihn auf #/coding neu herunter. Mehr unter [Coding-Pipeline](help:coding-pipeline).
